# 심심이 챗봇
**MongoDB와 Pinecone 벡터 DB를 결합하여 대화 내용을 주제별로 요약하고, 필요 시 과거의 기억을 스스로 인출하는 RAG 기반 챗봇 시스템**


## 소개
- **문제 정의**: 기존 챗봇은 대화가 길어지면 토큰 제한으로 인해 과거 맥락을 잊어버리거나, 휘발성 메모리에 의존하여 며칠 전 대화 내용을 기억하지 못하는 한계가 있음.
- **솔루션**: 
    1. **주제별 요약 엔진**: 매일 나눈 대화를 AI가 주제별로 자동 요약하여 데이터 효율화 및 검색 정확도 향상.
    2. **기억 인출**: GPT가 현재 질문에 과거 기억이 필요한지 스스로 판단하여 관련 정보를 검색하고 답변에 반영.

## 주요 구현 기술

### 1. 기억 시스템
- **기억 필요성 판단**: 모든 질문에 DB를 검색하는 비용을 줄이기 위해, GPT가 현재 질문이 과거 기억을 참조해야 하는 질문인지(True/False) 선제적으로 판단합니다.
- **벡터 유사도 검색**: Pinecone 벡터 DB를 통해 사용자 질문과 가장 유사한 과거 대화의 요약본 ID를 빠르게 찾아냅니다.
- **확률 기반 필터링**: 벡터 유사도 점수 외에도, 검색된 기억이 실제 질문에 적절한지 GPT가 다시 한번 유사도 확률을 검증하여 할루시네이션을 방지합니다.

### 2. 백그라운드 자가 요약 엔진
- **데몬 스레드 (Daemon Thread)**: 메인 서버 프로세스와 별개로 비동기적으로 동작하며, 1시간마다 실시간 대화 내용을 모니터링하고 처리합니다.
- **주제 중심 요약 알고리즘**: 대화를 의미 있는 주제별로 재구성하여 요약합니다.
- **자동 영속화**: 자정 이후 전날의 대화를 모두 조회하여 주제별로 요약하고, 벡터화하여 각 DB(Pinecone, MongoDB)에 자동 저장합니다.

### 3. Context 증강 및 답변 최적화
- **기억 부재 시 대응**: 질문에 필요한 기억을 찾지 못했을 경우, 무리하게 답변하지 않고 "기억이 나지 않는다"고 정직하게 답하도록 설계되었습니다.

## 작동 메커니즘

### [실시간 대화 흐름]
1. **메시지 입력**: 사용자가 "며칠 전 추천해준 노래 기억나?"라고 질문.
2. **검색 판단**: AI가 과거 기억 검색이 필요한 지 판단.
3. **유사도 검색**: 질문을 임베딩하여 **Pinecone**에서 관련 요약본 ID 추출.
4. **검증 및 인출**: **MongoDB**에서 해당 요약본 원문을 가져와 유사도 필터링 후 프롬프트에 결합.
5. **응답 생성**: 검색된 기억을 토대로 "그럼요, 트로이 시반의 노래를 추천해주셨죠!"라고 답변.

### [기록 저장 프로세스]
1. **대화 저장**: 실시간 대화 내용을 MongoDB에 보관.
2. **배치 처리**: 데몬 프로세스가 주기적으로 `build_memory` 수행.
3. **요약 및 변환**: GPT가 대화를 주제별로 요약하고 이를 벡터 데이터로 변환.
4. **기록 저장**: 요약본은 MongoDB에 저장하고 벡터는 Pinecone에 업서트한 후 원본 대화 삭제.
